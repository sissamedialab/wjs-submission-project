## 2026-11-11 — MR 187 review fixes: dynamic fields and required markers
**What:** Handled the four open review threads on MR 187 (issue 3330) one at a time, each analysed before any change: unsupported field kinds are logged where they are dropped, required textarea/select/email dynamic fields behave as required in the browser, and the co-authors section no longer carries a "Required" marker.
**Why:** The reviewer found that a `None` branch in `map_dynamic_field` was dead code, that a required textarea did not block the submit button, that a required select could never be left unanswered, and that co-authors (and ESM/administrative files) looked required when they are not.
**Decisions:**
- Thread 1: the reviewer's suggested `logger.error` in the dead branch was not applied as is. The real silent drop was the `kind__in=FIELD_SPECS` queryset filter, so filtering moved to `SubmissionStep1Form._supported_additional_fields()` (logs a warning per skipped element) and `map_dynamic_field` now raises `KeyError`. The first attempt simply dropped the filter, which would have made the `clean()` loops call `add_error()` on fields missing from the form; the filter stayed, just moved and made loud.
- Thread 2: blank choice added to every `select` (required or not) so nothing is preselected; side effect is that an optional select no longer stores its first option unless chosen. Required `textarea` gets `js_required` because django-tinymce renders no HTML `required` attribute and `detect_required.js` selects on `[required],[js_required]`. `email` switched to `EmailInput`.
- Thread 3: removed the unconditional "Required" line under "Select co-authors" (added in e97b4f7); the author list and the corresponding author keep their own markers.
- Thread 4: no change, already fixed by a4f9de2 (marker only for the manuscript file).
- Playwright verification was explicitly skipped for this unit of work: the diff changes what `detect_required.js` sees (`js_required`, blank select) and would normally get e2e coverage, but there is no dynamic textarea in code and a check would need a configured journal. Covered by unit tests only.

**Considered & dropped:** applying the reviewer's `logger.error` suggestion verbatim (would never fire); blank choice only for required selects (leaves the "first option silently saved" quirk on optional ones); a themes fix for the checkbox help-text indentation (belongs in wjs-themes, user chose not to open an issue).
