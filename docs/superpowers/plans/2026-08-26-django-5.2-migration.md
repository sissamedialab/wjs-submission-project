# wjs-submission-project Django 5.2 Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make `wjs-submission` (the `wjs_submission` Janeway plugin) work correctly under Django
5.2, verified via its own real test suite run against the already-migrated `janeway-5.2` checkout.

**Architecture:** No structural changes. Two files need a mechanical modernization
(`django-upgrade`-driven); the rest of the 48-file plugin needs only dependency-pin changes. This
repo has a genuine `tests/` suite designed to run against a live Janeway checkout — that's the
primary verification mechanism, not a manual page-check.

**Tech Stack:** Python 3.11+, Django 5.2, `django-upgrade`, `ruff`, `pytest`/`pytest-django`.

**Spec:** `docs/superpowers/specs/2026-08-26-django-5.2-migration-design.md` (this repo).

## Global Constraints

- Python floor: `>= 3.11` (confirmed for all five `wjs-*` repos in this migration effort). This
  repo's own `StrEnum` usage (`account_validation.py`) needed a `>=3.11` floor regardless — with
  the effort-wide floor now also `3.11`, this is simply the standard floor, not a per-repo
  exception as the spec had framed it before that confirmation.
- Django target: `5.2`.
- No behavioral change.
- `django-bootstrap5 >= 26.2` (matches `wjs-themes`, resolves the prior `~= 25.2` pin conflict).
- Package version bumps to `2.1.0`.
- No changes to `wjs-themes`, `wjs-search-user`, `wjs-utils-project`, or `wjs-profile-project`
  themselves.
- **A local, uncommitted, staged one-line edit to `account_validation.py` exists in this repo's
  main checkout (not this worktree) — do not touch it.** This worktree's copy of that file, being
  based on the `docs/django-5.2-migration-spec` branch, does not include that uncommitted edit;
  when this plan's changes are eventually merged back, be aware the main checkout has that extra
  pending change.

### Task 1: Apply `django-upgrade`'s modernization rewrites

**Files:**
- Modify: `wjs/plugins/wjs_submission/models.py`
- Modify: `wjs/plugins/wjs_submission/advanced_admin/advanced_admin.py`

- [ ] **Step 1: Run `django-upgrade` over the whole plugin**


- [ ] **Step 3: Commit**

### Task 5: Fix the second unsaved-instance regression in `workflow.py`

**Added after the final whole-branch review found a second instance of the exact bug Task 4
already fixed once**, hidden by test coverage luck: `SubmissionConfiguration.comments_to_the_editor`
defaults to `True`, and the only test touching it sets it `True`, so the `or`-chain at
`step1/forms.py:129-133` (`... or is_revision_full(self.instance) or is_revision_confirm(self.instance)`)
never short-circuits into evaluating these two calls in the test suite — but on a real journal
configured with `comments_to_the_editor = False`, it does, on an unsaved `Article` instance (step 1
of a first-time submission, via `SubmissionStep1View`'s `CreateView` with no `article_id`).

`is_revision_confirm`, `is_revision_metadata`, and `is_revision_full` (`wjs/plugins/wjs_submission/workflow.py:174-204`)
each guard only `if not article: return False` — but Django model instances have no `__bool__`
override, so an unsaved `Article()` is truthy, same root cause as Task 4's fix. Each function then
calls `RevisionStorage.objects.get(article=article)`, which raises
`ValueError: Model instances passed to related filters must be saved.` on Django 5.x for an unsaved
instance (verified: `RevisionStorage.article` is a `OneToOneField`, routing through the same
`get_normalized_value` code path as Task 4's `FieldAnswer` case). **Impact:** any journal with
`comments_to_the_editor = False` gets an unhandled `ValueError` on step 1 of the submission
wizard — the plugin's primary entry point — on both GET and POST, under Django 5.2.

**Files:**
- Modify: `wjs/plugins/wjs_submission/workflow.py` (three functions: `is_revision_confirm`,
  `is_revision_metadata`, `is_revision_full`)
- Test: `tests/test_forms.py` (or wherever this repo's existing form/workflow tests for step1 live —
  follow the existing test file's convention)

**Interfaces:** None — internal guard fix, same function signatures.

- [ ] **Step 1: Write a regression test**

Add a test that instantiates `SubmissionStep1Form` with no `instance=` (so `self.instance` is an
unsaved `Article()`) and with the journal's `SubmissionConfiguration.comments_to_the_editor` set to
`False`, then confirms form construction/validation does not raise. Follow this repo's existing
test conventions (`.claude/rules/tests.md`): descriptive assertion messages, fixtures from
