# wjs-submission-project: Django 5.2 Migration — Design

## Context

This is the fourth of five independent `wjs-*` plugin repos being ported to Django 5.2, following
the core `janeway-5.2` migration (Django 4.2.30 → 5.2.17, Python floor `>=3.9` → verified
`3.10`–`3.13`) on branch `migration/1.8-phase7-pep440-compat-release`, and after `wjs-themes`,
`wjs-search-user`, and `wjs-utils-project` (see their own specs, in their respective repos'
`docs/superpowers/specs/2026-08-26-django-5.2-migration-design.md`).

Unlike the prior three repos, `wjs-submission-project` is a real Janeway plugin
(`wjs/plugins/wjs_submission/`) with an actual `tests/` directory and CI that runs it — so this
port can lean on genuine automated verification, not only static review.

**Amendment (at planning time):** the Python floor across all five repos is now confirmed as
**3.11**. This repo's `python_requires >= 3.11` is therefore no longer a per-repo exception
diverging from a 3.10 floor (as framed below) — it's simply the standard floor everyone uses,
which happens to already match what this repo's own `StrEnum` usage required.

A local, uncommitted, staged one-line edit to `wjs/plugins/wjs_submission/account_validation.py`
exists in this checkout and is explicitly **not touched** by this spec or its implementation, per
your direction.

## Goal

Make `wjs-submission` work correctly under Django 5.2, with no behavioral change, verified via its
own real test suite run against the already-migrated `janeway-5.2` checkout.

## Repo shape (as found)

- A Janeway plugin under `wjs/plugins/wjs_submission/`: 104 `.py` files, 22 migrations, a
  multi-step submission-wizard layout (`step1`–`step8`), plus `correction/`, `revision/`,
  `events/`, `files/`, `helpers/`, `management/`, `templatetags/`.
- `setup.cfg`: package `wjs-submission`, version `2.0.17.dev1`. `install_requires` includes
  `redis`, `django-redis`, `django-bootstrap5 ~= 25.2`, `defusedxml`, `wjs-themes >= 2.0.18`,
  `wjs-user-search >= 2.0.3`, `django-q2`, `channels`, `channels-redis`, `msgpack~=1.2.1`.
  `[options.extras_require] test` pins `pytest >= 9.0, < 10`, `pytest-django < 4.13` (with a
  comment: "4.13+ needs a Django attribute absent in Django 4.2"), `pytest-mock`,
  `pytest-freezegun`, `pytest-xdist`, `pytest-reverse`.
- A deprecation-pattern grep (`CheckConstraint`, `index_together`,
  `django.contrib.postgres.fields.JSONField`, `ugettext`, `force_text`, `is_ajax`,
  `django.utils.six`, `django.conf.urls.url`, `providing_args`, `assertQuerysetEqual`) across the
  whole plugin found **nothing**. This codebase is already fairly current: `pyproject.toml`'s
  `ruff` config targets `py311`, and CI already runs on the `python:3.13` image.
- **Cross-plugin coupling** (same pattern as the prior repos): `account_validation.py` imports
  `wjs.jcom_profile.constants.PROFESSIONS` (`wjs-profile-project`) at module level, in addition to
  the declared `wjs-themes`/`wjs-user-search` dependencies.
- **Two concrete Django/Python-version findings**, both resolved per your direction (see Changes):
  1. `account_validation.py` (already in `HEAD`, not part of the uncommitted staged edit) defines
     `class ProfileCompletionStatus(StrEnum)` — `from enum import StrEnum` requires **Python
     3.11+**, conflicting with the 3.10 floor established across the rest of this migration
     effort. No `python_requires` is declared anywhere in this repo today, so nothing currently
     documents or enforces this gap.
  2. `django-bootstrap5 ~= 25.2` (locks to `25.2.x`) is incompatible with `wjs-themes`' newly
     added `django-bootstrap5 >= 26.2` floor — the two constraints can't both be satisfied by one
     installed version.
- **Real test suite**: `tests/` at the repo root, run via `pytest` from a sibling `janeway/src`
  checkout (documented in this repo's own `.claude/rules/tests.md`):
  `DJANGO_SETTINGS_MODULE = "wjs.defaults.tests_submission"`, config lives in `pyproject.toml`'s
  `[tool.pytest.ini_options]` (no `pytest.ini`). Requires: this repo `pip install -e .[test]`ed
  into the host Janeway virtualenv, and `wjs/plugins/wjs_submission` symlinked into that
  checkout's own `plugins/` directory.
- CI (`.gitlab-ci.yml`) already runs a real `run-tests` job (`pytest ... -n 6 --create-db`) against
  a Docker image `registry.gitlab.sissamedialab.it/wjs/janeway/debian-python-git-janeway:${JANEWAY_VERSION}`,
  with `JANEWAY_VERSION` defaulting to `"production"` — a **pre-migration** Janeway build. This CI
  job will not reflect Django 5.2 until a Django-5.2 Janeway image is published; that publishing
  is a `janeway-5.2` release concern, out of scope for this spec.

## Approach

Same tool-assisted method as the prior repos (`django-upgrade --target 5.2` + `ruff`), but at this
scale (104 files) manual review is tooling-output-driven and spot-checked on higher-risk areas
(the `step1`–`step8` wizard, `account_validation.py`) rather than a full file-by-file read —
proportionate the same way the template sweep was scoped for `wjs-themes`. The deprecation-pattern
grep already found nothing, consistent with the pattern in the prior three repos.

Considered and rejected:
- **Fix the `StrEnum` usage instead of carving out a Python-version exception**: rejected per your
  direction — declare `python_requires >= 3.11` for this repo specifically instead.
- **Lower `wjs-themes`' `django-bootstrap5` floor to resolve the pin conflict, instead of raising
  this repo's**: rejected per your direction — loosen this repo's pin to `>= 26.2` to match.
- **Skip live verification, static review only**: rejected — unlike the prior three repos, this
  one has a genuine test suite designed to run against a live Janeway checkout, and `janeway-5.2`
  is available as exactly that checkout right now. Not using it would discard real signal.

## Changes

1. **Python fixes** across the plugin as found by `django-upgrade --target 5.2` + spot-checked
   manual review. Scope is whatever those tools/review turn up; expected small given the clean
   grep sweep.
2. **`setup.cfg`**:
   - Add `python_requires = >= 3.11` (documented exception to the migration's 3.10 floor,
     justified by the pre-existing `StrEnum` usage).
   - `django-bootstrap5 ~= 25.2` → `django-bootstrap5 >= 26.2` (matches `wjs-themes`, already
     verified installed and working in the `janeway-5.2` venv).
   - `pytest-django < 4.13` → drop the upper bound. The documented reason for the ceiling was
     Django-4.2-specific ("a Django attribute absent in Django 4.2"); running on Django 5.2
     removes that blocker.
   - Bump `version` from `2.0.17.dev1` to `2.1.0`. `wjs-profile-project`'s
     `wjs-submission >= 2.0.16` pin is a loose `>=`, so this doesn't require a coordinated update
     there (unlike `wjs-utils-project`'s tight `~=` pin).
   - `wjs-themes >= 2.0.18` and `wjs-user-search >= 2.0.3` are already satisfied by those repos'
     new `2.1.0` releases — no change needed to those two lines.
3. No CI image change (`python:3.13` already current). The stale `JANEWAY_VERSION: "production"`
   Docker image is flagged, not fixed, here (see Repo shape above).
4. No changes to `wjs-profile-project`, `wjs-themes`, `wjs-search-user`, or `wjs-utils-project`.

## Verification

1. Run `django-upgrade --target 5.2` and `ruff` over the plugin; apply and review fixes.
2. Spot-check higher-risk areas (`step1`–`step8`, `account_validation.py`) manually.
3. `pip install -e .[test]` this repo into the `janeway-5.2` checkout's virtualenv.
4. Symlink `wjs/plugins/wjs_submission` into `janeway-5.2/src/plugins/wjs_submission`.
5. Confirm `wjs-themes` and `wjs-search-user` are also editable-installed into the same venv
   (both already ported — see their specs).
6. From `janeway-5.2/src`, run `pytest --create-db -n7 <path-to-wjs-submission-project>`, per this
   repo's own documented local workflow.
7. **Honest caveat, not an assumption of success**: because `account_validation.py` imports
   `wjs.jcom_profile` (from the not-yet-ported `wjs-profile-project`), a failure in this run may
   originate from *that* package's own pending Django-5.2 incompatibilities rather than from this
   repo's code. If so, this is tracked as blocking on `wjs-profile-project`'s port (the next and
   final spec in this effort), not treated as a defect introduced here.

## Out of scope

- Publishing a Django-5.2-compatible Janeway CI Docker image (a `janeway-5.2` release concern).
- Porting `wjs-profile-project` — it gets its own, final spec.
- Resolving any `wjs.jcom_profile`-side failures surfaced during this repo's verification attempt
  (tracked above, not fixed here).
- Changing the `pytest >= 9.0, < 10` pin — unaffected by this migration, left as-is.
